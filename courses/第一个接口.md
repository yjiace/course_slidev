## 1、前端与后端的定义

*   **前端 (Frontend):** 前端是指用户直接看到的和交互的界面部分。它负责用户体验，包括网页的布局、样式、交互效果等。前端技术主要涉及 HTML（结构）、CSS（样式）、JavaScript（行为）以及各种前端框架（如 React、Vue、Angular）和库。前端的目的是将后端提供的数据以用户友好的方式展示出来，并响应用户的操作，将用户的请求传递给后端。

*   **后端 (Backend):** 后端是指在服务器上运行的应用程序部分。它负责处理业务逻辑、数据存储、用户认证、安全性等。后端技术涉及各种编程语言（如 Java、Python、Node.js）、后端框架（如 Spring Boot、Django、Express.js）、数据库（如 MySQL、PostgreSQL、MongoDB）以及服务器环境的配置和管理。后端的目的是接收前端发送的请求，进行处理，并将结果返回给前端。

===
*   **前端 (Frontend):**  相当于餐厅里的“服务员”。
    *   负责用户**看到**和**操作**的部分。
    *   这包括网页的布局、颜色、文字、图片，以及按钮、输入框等交互元素。
    *   前端的主要任务是**展示信息**给用户，并**收集用户输入**。
    *   常用的前端技术包括 HTML (负责结构)、CSS (负责样式)、JavaScript (负责交互)。
    *   你可以把前端想象成你打开一个网站时，所看到的所有内容和可以点击操作的东西。

*   **后端 (Backend):** 相当于餐厅里的“厨师”。
    *   负责**处理**前端发送过来的请求，进行数据存储、计算等**幕后工作**。
    *   前端收集到的数据会交给后端处理。后端处理完毕后，会将结果返回给前端展示。
    *   后端的主要任务是**处理业务逻辑**、**存储数据** (例如用户信息、商品信息等)，并**提供数据接口**给前端。
    *   常用的后端技术有很多，例如 Java、Python、PHP、Node.js 等。在 Java Web 项目中，后端自然就是使用 Java 技术。
    *   你可以把后端想象成你看不到的服务器上的程序，它在默默地处理各种事情，保证网站的正常运行。

## 2、接口的定义（路径、请求方式、参数、返回值），如何写接口

*   **路径 (Path/Endpoint):** 用于唯一标识一个接口在服务器上的地址。例如：`/users`、`/products/{id}`。

*   **请求方式 (HTTP Method):** 定义了对资源的操作类型。常见的请求方式有：
    *   **GET:**  通常用于**获取**数据。例如，前端想获取商品列表，可以向后端发送一个 GET 请求到 `/api/products` 这个 URL。
    *   **POST:** 通常用于**提交**数据，让后端进行创建操作。例如，前端用户注册时，会将用户信息通过 POST 请求发送到 `/api/register` 这个 URL。
    *   **PUT:**   通常用于**更新**已有的数据。例如，前端用户修改个人信息后，可以通过 PUT 请求发送到 `/api/users/{id}` (其中 `{id}` 是用户ID) 这个 URL。
    *   **DELETE:** 通常用于**删除**数据。例如，前端想删除某个商品，可以发送 DELETE 请求到 `/api/products/{id}` 这个 URL。

*   **参数 (Parameters):** 前端传递给后端的数据。参数可以分为：
    *   **路径参数 (Path Variables):** 嵌入在URL路径中的参数，例如 `/users/{id}` 中的 `{id}`。
    *   **查询参数 (Query Parameters):** 附加在URL后面的参数，以 `?` 开头，多个参数之间用 `&` 连接，例如 `/users?name=John&age=30`。
    *   **请求体参数 (Request Body):** 通常用于 `POST`、`PUT` 等请求，数据以 JSON、XML 等格式放在请求体中发送。

*   **返回值 (Response):** 后端处理完请求后返回给前端的数据。返回值通常包含：
    *   **状态码 (HTTP Status Code):** 表示请求的处理结果，例如 `200` (成功)、`404` (未找到)、`500` (服务器错误)。
    *   **响应体 (Response Body):** 包含实际的数据，通常以 JSON 或 XML 格式返回。

## 3、JSON 格式

**JSON (JavaScript Object Notation)** 是一种轻量级的数据交换格式，它非常易于阅读和编写，并且很容易被计算机解析和生成，因此在前后端数据传输中被广泛使用。

1.  **键值对 (Key-Value Pairs):** 这是 JSON 最基本的组成部分。一个键值对包含一个**键 (Key)** 和一个对应的**值 (Value)**。
    *   **键 (Key):** 必须是一个**字符串**，并且通常用双引号 `"` 包裹。
    *   **值 (Value):** 可以是以下几种类型：
        *   **字符串 (String):**  用双引号 `"` 包裹。例如: `"这是一个字符串"`
        *   **数字 (Number):**  可以是整数或浮点数。例如: `123`, `3.14`, `-10`
        *   **布尔值 (Boolean):**  只有两个值：`true` (真) 或 `false` (假)。注意是小写。
        *   **空值 (Null):**  用 `null` 表示。注意是小写。
        *   **对象 (Object):**  由花括号 `{}` 包裹的无序的键值对集合。对象可以嵌套。
        *   **数组 (Array):** 由方括号 `[]` 包裹的有序的值的集合。数组中的值可以是任意 JSON 支持的类型，包括对象和数组，也可以嵌套。
===
一个 JSON 对象是由**一个或多个键值对**组成的，键值对之间用**逗号 `,`** 分隔，整个对象被**花括号 `{}`** 包裹。

例如，一个表示用户信息的简单 JSON 对象：

```json
{
    "name": "张三",
    "age": 30,
    "isStudent": false,
    "address": {
        "city": "北京",
        "street": "朝阳大街"
    },
    "hobbies": ["游泳", "阅读"],
    "mobile": null
}
```

**让我们分解一下这个例子：**

*   `"name": "张三"`:  一个键值对，键是字符串 `"name"`，值是字符串 `"张三"`.
*   `"age": 30`: 一个键值对，键是字符串 `"age"`，值是数字 `30`.
*   `"isStudent": false`: 一个键值对，键是字符串 `"isStudent"`，值是布尔值 `false`.
*   `"address": { ... }`: 一个键值对，键是字符串 `"address"`，值是一个**嵌套的 JSON 对象**。这个嵌套对象包含了用户的城市和街道信息。
*   `"hobbies": [...]`: 一个键值对，键是字符串 `"hobbies"`，值是一个 **JSON 数组**。这个数组包含了用户的两个爱好，都是字符串类型的值。
*   `"mobile": [...]`: 一个键值对，键是字符串 `"mobile"`，值为空，用`null`表示。

**JSON 数组** 由**零个或多个值**组成，这些值之间用**逗号 `,`** 分隔，整个数组被**方括号 `[]`** 包裹。

例如，一个包含多个用户信息的 JSON 数组：

```json
[
    {
        "name": "李四",
        "age": 25
    },
    {
        "name": "王五",
        "age": 35
    }
]
```

## 4、如何写接口 (使用 Spring Boot)

以下是一个使用 Spring Boot 编写的简单接口示例，用于获取用户的姓名：

1.  **创建 Spring Boot 项目:** （略过，假设您已经创建了一个 Spring Boot 项目）

2.  **创建一个 Controller 类:**

创建一个名为 `UserController.java` 的类，并添加 `@RestController` 注解，表示这是一个处理 HTTP 请求的控制器。添加 `@RequestMapping("/api/users")` 注解，指定该控制器下所有接口的根路径为 `/api/users`。

在 `UserController.java` 中：

```java
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.web.bind.annotation.RequestMapping;

import java.util.HashMap;
import java.util.Map;

@RestController
@RequestMapping("/api/users")
public class UserController {

    @GetMapping("/name")
    public Map<String, String> getUserName(@RequestParam(value = "id", defaultValue = "1") String id) {
        Map<String, String> response = new HashMap<>();
        if (id.equals("1")) {
            response.put("name", "张三");
        } else if (id.equals("2")) {
            response.put("name", "李四");
        } else {
            response.put("name", "未知用户");
        }
        return response;
    }
}
```
**接口定义解释:**

*   **路径:** `/api/users/name`
*   **请求方式:** `GET` (`@GetMapping`)
*   **参数:** `id` (查询参数，通过 `@RequestParam` 注解获取，`defaultValue` 设置了默认值为 "1")
*   **返回值:** 一个 `Map<String, String>` 对象，Spring Boot 会自动将其转换为 JSON 格式作为响应体返回。例如：`{"name": "张三"}`。

3.  **运行 Spring Boot 应用:** 启动您的 Spring Boot 应用程序。默认情况下，它会在 8080 端口运行。

## 5、前端如何发送请求（路径、请求方式、参数、返回值），前后端如何对接接口

**前端发送请求 (使用 HTML 和 JavaScript):**

我们可以使用 JavaScript 的 `fetch` API 或 `XMLHttpRequest` 对象在前端发送 HTTP 请求。以下是一个使用 `fetch` API 的示例 HTML 文件 (`index.html`):

``` html
<!DOCTYPE html>
<html>
<head>
    <title>前端调用接口</title>
    <meta charSet="utf-8"/>
</head>
<body>
    <h1>获取用户姓名</h1>
    <label for="userId">用户ID: </label>
    <input type="text" id="userId" value="1"><br><br>
    <button onclick="getUserName()">获取姓名</button>
    <div id="result"></div>

    <script>
        function getUserName() {
            const userId = document.getElementById("userId").value;
            const url = `/api/users/name?id=${userId}`; // 接口路径和查询参数

            fetch(url, {
                method: 'GET', // 请求方式
            })
            .then(response => {
                if (!response.ok) {
                    throw new Error(`HTTP error! status: ${response.status}`);
                }
                return response.json(); // 解析 JSON 格式的返回值
            })
            .then(data => {
                document.getElementById("result").innerText = `用户姓名: ${data.name}`; // 处理返回值
            })
            .catch(error => {
                document.getElementById("result").innerText = `请求失败: ${error}`;
            });
        }
    </script>
</body>
</html>
```

**前端发送请求解释:**

*   **路径:** `/api/users/name?id=${userId}` (根据用户输入的 `userId` 动态构建 URL，`?id=` 表示查询参数)
*   **请求方式:** `GET` (在 `fetch` 方法的配置中指定)
*   **参数:** `id` (通过查询参数的方式附加到 URL 上)
*   **返回值:** `fetch` API 返回一个 Promise，通过 `.then()` 方法处理响应。
    *   第一个 `.then()` 检查响应状态是否成功 (`response.ok`)，如果失败则抛出错误。
    *   第二个 `.then()` 使用 `response.json()` 将响应体解析为 JSON 对象 (`data`)。
    *   通过 `data.name` 获取后端返回的姓名，并显示在 `div#result` 中。
*   `.catch()` 方法用于捕获请求过程中发生的错误。
===
**前后端如何对接接口:**

1.  **约定接口规范:** 前后端开发人员需要事先约定好接口的路径、请求方式、参数（名称、类型、是否必填）、返回值（数据结构、字段名称、数据类型）以及错误码等。可以使用文档（如 Swagger/OpenAPI）或会议沟通的方式进行约定。

2.  **前端发送请求:** 前端根据约定的接口规范，使用相应的 HTTP 方法和路径，将需要的参数发送给后端服务器。

3.  **后端接收和处理请求:** 后端 Spring Boot 应用接收到前端发送的请求，根据请求的路径和方式，找到对应的 Controller 方法进行处理。后端会从请求中获取参数，执行业务逻辑，并生成响应数据。

4.  **后端返回响应:** 后端将处理结果封装成约定的格式（通常是 JSON），设置相应的 HTTP 状态码，并通过 HTTP 响应返回给前端。

5.  **前端处理响应:** 前端接收到后端的响应，根据 HTTP 状态码判断请求是否成功。如果成功，则解析响应体中的数据，并将其展示在用户界面上。如果失败，则根据状态码和错误信息进行相应的处理，例如显示错误提示。
