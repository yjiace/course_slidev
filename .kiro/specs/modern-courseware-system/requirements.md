# 需求文档

## 简介

本系统旨在为软件学院开发一套现代化课件系统，替代传统PPT，满足课堂大屏演讲场景需求。系统采用VitePress和Slidev混合架构：VitePress负责课程门户、导航和文档阅读功能；Slidev专注课堂幻灯片展示。系统全部使用中文界面和内容。

## 术语表

- **课件系统**：基于Web技术的教学内容展示平台，包含课程门户和演讲课件两部分
- **VitePress**：基于Vite的静态站点生成器，用于构建课程门户和文档
- **Slidev**：基于Vue的演示文稿工具，用于创建和展示课堂幻灯片
- **课程门户**：使用VitePress构建的课程导航和文档阅读界面
- **演讲课件**：使用Slidev构建的课堂幻灯片展示系统
- **大屏演讲场景**：教室投影仪或大屏幕上进行的课堂教学演示
- **教研室**：按照技术栈或专业方向划分的课程分类，用于组织和管理相关课程
- **分类**：课程的主要归属类别，通常对应教研室或技术栈，每个课程只属于一个分类
- **标签**：课程的主题关键词标记，用于描述课程涉及的技术点或知识领域，每个课程可以有多个标签
- **腾讯云EdgeOne**：腾讯云提供的边缘计算和CDN加速平台，用于部署静态网站和提供全球访问加速
- **增量构建**：仅构建发生变更的课程文件，复用未变更课程的缓存结果，以减少构建时间
- **CI/CD**：持续集成和持续部署，指代码提交后自动执行构建、测试和部署的流程

## 需求

### 需求 1：课程门户基础架构

**用户故事：** 作为教师，我希望有一个清晰的课程门户网站，以便学生能够浏览课程目录和访问课程资料

#### 验收标准

1. 当系统启动时，课件系统应当使用VitePress框架初始化课程门户
2. 当用户访问课程门户时，课件系统应当展示中文界面的课程目录导航
3. 当用户点击课程章节时，课件系统应当显示对应的文档内容
4. 当用户浏览文档时，课件系统应当提供侧边栏导航功能
5. 当课程内容更新时，课件系统应当支持热重载预览

### 需求 2：演讲课件展示功能

**用户故事：** 作为教师，我希望能够在课堂上使用现代化的幻灯片进行演讲，以便提升教学效果

#### 验收标准

1. 当教师准备授课时，课件系统应当使用Slidev框架加载演讲课件
2. 当教师在大屏上展示时，课件系统应当以全屏模式呈现幻灯片内容
3. 当教师切换幻灯片时，课件系统应当支持键盘方向键和鼠标点击操作
4. 当教师需要标注时，课件系统应当提供绘图工具功能
5. 当教师展示代码时，课件系统应当支持代码语法高亮显示

### 需求 3：课程自动发现与管理

**用户故事：** 作为教师，我希望创建Slidev课程后能自动出现在课程门户中，以便无需手动维护课程列表

#### 验收标准

1. 当教师使用Slidev创建新课程时，课件系统应当自动扫描并将该课程添加到门户列表
2. 当教师删除Slidev课程时，课件系统应当自动从门户列表中移除该课程
3. 当系统构建时，课件系统应当遍历课程目录并生成课程索引
4. 当课程元数据变更时，课件系统应当自动更新门户中的课程信息
5. 当开发环境运行时，课件系统应当监听课程文件变化并实时更新门户

### 需求 4：教研室分类与标签管理

**用户故事：** 作为教师，我希望课程能够按照教研室（技术栈）自动分类并支持标签标注，以便学生按专业方向和主题查找课程

#### 验收标准

1. 当教师创建Slidev课程时，课件系统应当从课程元数据中提取分类和标签信息
2. 当系统生成课程索引时，课件系统应当自动识别所有涉及的分类和标签
3. 当门户首页加载时，课件系统应当按照分类分组展示课程列表
4. 当新增课程包含新分类或标签时，课件系统应当自动将其添加到索引系统
5. 当学生浏览首页时，课件系统应当显示所有分类及其对应的课程数量

### 需求 5：标签筛选与关联推荐

**用户故事：** 作为学生，我希望通过标签快速找到同类课程，以便系统化学习相关知识

#### 验收标准

1. 当学生查看课程详情时，课件系统应当显示该课程的所有标签
2. 当学生点击某个标签时，课件系统应当展示所有包含该标签的课程列表
3. 当学生浏览课程时，课件系统应当在侧边栏推荐具有相同标签的相关课程
4. 当门户首页加载时，课件系统应当提供标签云或标签列表供快速筛选
5. 当学生使用搜索功能时，课件系统应当支持按标签进行过滤

### 需求 6：学生友好的门户界面

**用户故事：** 作为学生，我希望能够在简洁的界面中快速找到需要的课程，无论课程数量多少

#### 验收标准

1. 当课程数量较少时，课件系统应当以卡片网格布局展示所有课程
2. 当课程数量增多时，课件系统应当提供分类筛选和搜索功能
3. 当学生访问门户首页时，课件系统应当优先显示课程列表而非复杂导航
4. 当学生查找课程时，课件系统应当提供清晰的课程标题和描述信息
5. 当学生浏览课程时，课件系统应当使用大字体和高对比度设计以提升可读性

### 需求 7：双系统集成与导航

**用户故事：** 作为用户，我希望在VitePress门户和Slidev课件之间无缝切换，以便获得流畅的学习体验

#### 验收标准

1. 当用户在VitePress门户浏览时，课件系统应当提供"进入演讲模式"的链接按钮
2. 当用户点击演讲模式链接时，课件系统应当在新标签页打开对应的Slidev课件
3. 当用户在Slidev课件中时，课件系统应当提供返回课程门户的导航链接
4. 当系统部署时，课件系统应当确保VitePress和Slidev共享统一的基础路径
5. 当用户访问课件时，课件系统应当保持一致的中文界面风格

### 需求 8：开发与构建工作流

**用户故事：** 作为开发者，我希望有便捷的开发和构建流程，以便高效维护课件系统

#### 验收标准

1. 当开发者启动开发环境时，课件系统应当同时运行VitePress和Slidev的开发服务器
2. 当开发者修改内容时，课件系统应当自动刷新预览
3. 当开发者构建生产版本时，课件系统应当生成VitePress和Slidev的静态文件
4. 当系统部署时，课件系统应当将所有静态资源输出到统一目录
5. 当开发者配置项目时，课件系统应当提供清晰的中文配置文件和注释

### 需求 9：CI/CD自动构建与增量优化

**用户故事：** 作为开发者，我希望GitHub代码更新时能自动构建课程，并通过增量构建优化减少构建时间

#### 验收标准

1. 当GitHub仓库有新提交时，课件系统应当自动触发构建流程
2. 当构建开始时，课件系统应当检测变更的课程文件并仅构建受影响的课程
3. 当课程未变更时，课件系统应当复用上次构建的缓存结果
4. 当VitePress门户配置变更时，课件系统应当重新生成课程索引但保留课程构建缓存
5. 当构建完成时，课件系统应当自动部署到EdgeOne平台

### 需求 10：腾讯云EdgeOne部署支持

**用户故事：** 作为运维人员，我希望能够将课件系统部署到腾讯云EdgeOne，以便提供高性能的全球访问服务

#### 验收标准

1. 当系统构建完成时，课件系统应当生成符合EdgeOne要求的静态资源结构
2. 当配置部署时，课件系统应当提供EdgeOne部署的配置文件和说明文档
3. 当静态资源上传时，课件系统应当确保所有资源路径正确适配EdgeOne环境
4. 当用户访问时，课件系统应当通过EdgeOne的CDN加速正常加载所有页面和资源
5. 当系统更新时，课件系统应当支持增量部署到EdgeOne平台
